## The quadlet question is answered, and the real blocker is ticket 260

**240 — done, `13a76a9`.** There is no replacement key: quadlet's `[Volume]` takes
only `podman volume create` arguments and no host path, so a `.volume` unit cannot
express a btrfs subvolume. Volumes now bind by subvolume path; the template is
deleted. Eight of nine `t40-*` green. `t40-untrusted` fails identically at HEAD —
verified by stashing — so it is separate, not a regression.

**A live escape surface closed on the way:** `Mount=` was in neither refusal list and
the mount guard read only `Volume=`, so a repository could write
`Mount=type=bind,source=/,destination=/host` and nothing looked at it.

**250 — answered, `06d79d4`, no code needed.** The premise was wrong. The generator
is installed and enabled, and the manager's own `daemon-reload` writes a 1516-byte
`web.service`, byte-identical to running it by hand. Both causes the ticket named are
false: `/run/user/<uid>` exists and is service-owned, and **a user manager has no
`systemd/user/` level** — it writes to `$XDG_RUNTIME_DIR/systemd/generator{,.late}`.
An earlier probe asserted on a path that does not exist and read "produced nothing"
out of a `grep` of a missing file.

**260 — the blocker, measured.** The deny is `daddr 127.0.0.0/8 -j DROP` and it drops
the service uid's DNS packet:

```
DENY_COUNTER_BEFORE=0
DENY_COUNTER_AFTER=1
```

spec 7.7's "the deny does not touch name resolution" is true only of traffic from
*inside* a container. `podman pull` runs on the **host** as the service user, through
`OUTPUT`, which jumps to `guarden-svc` — so the resolver is unreachable from every
service uid and **no first deploy of a new workload can complete.** Needs an ADR.

**A separate host finding:** `/usr/sbin/iptables` is **nft** and guarden's rules are in
**iptables-legacy**, because `ferm` invokes `iptables` by name. A host pointing at nft
would carry guarden's rules where no operator tool reads them.
